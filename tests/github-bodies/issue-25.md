As a Python developer I want an edit to a cell that a formula depends on to leave a document Numbers displays correctly, so that a script editing a formula-laden file does not quietly produce numbers that disagree with the arithmetic behind them.

1. A save that changes a cell some formula depends on never produces a file that silently displays a stale result. Either Numbers shows a value consistent with the edit, or pybers declines to write and says which formula would be stranded.
   1. Numbers is the only authority on whether a displayed result is consistent, so this is settled by a golden file opened once in Numbers and confirmed, never by a pybers round trip.
   1. `tests/golden/20-formula-shapes-multisheet-edited.numbers` is the case to close. It currently displays 55 in `A11`, holding `SUM(A1:A10)`, after its operands were raised to sum to 10055.
   1. Whether `refs_to_dirty` makes Numbers recalculate is settled by measurement inside this ticket, and the answer is written into `findings-02-formulas.md` whichever way it goes, so that the losing method is on record as tried rather than as never considered.
2. pybers never evaluates a formula. Every stored result is one Numbers computed, and this library computes none of them.
3. ~~A declined save names the cell that was edited and the formula whose result would go stale, and it declines before anything is written, leaving the file exactly as it was.~~ **Struck 2026-09-02, and deliberately not implemented.** This specified the losing half of AC 1. The measurement under AC 1.iii settled AC 1 as the recalculation half, so no save is ever declined for this reason and a decline path would be code nothing reaches. AC 1 stands unchanged and still permits either outcome; this records which one it took.
4. Editing a cell that no formula depends on behaves as it does now and costs no more than it does now.
5. `Document.save` states in its own docstring what it does to a formula depending on an edited cell, so a caller meets the answer where they meet the method rather than in the writer's source.

## SPEC

- **Numbers does not recalculate on open**, measured 2026-09-02 against the golden named above: the file opened with no warning and no repair prompt, and `A11` still showed the result cached before the edit. Waiting for Numbers to notice by itself is therefore not an option, and `findings-02-formulas.md` records the measurement.
- **Apple ships a channel for saying which cells moved.** `TSCE.CalculationEngineArchive` field 15 is `refs_to_dirty`, a reference to a `TSCE.ReferencesToDirtyArchive` carrying `to_dirty_cells`, `to_dirty_owner_ids` and `to_dirty_range_refs`. All 46 calculation engines in the corpus carry one and every one of them serializes to zero bytes, because a clean save has nothing pending. Whether populating it makes Numbers recalculate is unmeasured, and finding out is what decides between the two halves of AC 1.
- **A formula cell caches its result and its value slot is typed by that result**, per `findings-02-formulas.md`, so a stale value is indistinguishable from a genuine one by inspection. That is why this fails silently rather than loudly, and why AC 1 cannot be checked by reading the file back.
