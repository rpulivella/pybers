As a maintainer I want a published code of conduct so that a contributor knows which behavior ends their participation, and so that acting on it settles the matter rather than opening a debate.

## Acceptance criteria

1. `CODE_OF_CONDUCT.md` exists at the repository root, where GitHub reads it into the Community Standards panel and links it from a new issue.
2. The document names the behavior this project refuses, in the terms this project means them: disrespect toward any person, hostility, commentary that helps nobody, deliberate distraction, and clutter left in an issue or a pull request.
3. The document states that the standard applies to every repository space alike, which is issues, pull requests, comments, commit messages, reviews and discussions.
4. The document states what a maintainer may do about a violation, which is edit or remove the content, close the thread, and block the account, and states that none of it is owed a warning first.
5. The document names the single address a violation is reported to, and states that a report is read by the maintainers alone.
6. The document states that the maintainers hold themselves to the same standard, so that the document reads as the project's terms rather than as one person's.
7. `README.md` and `CONTRIBUTING.md` each link the document, and neither restates its terms.

## Constraints

1. Whether this adopts the Contributor Covenant or is written for this project is open. The Covenant is what a contributor recognizes and what GitHub's panel expects, while a document written here can say the short specific things AC 2 asks for, and the two are combinable.
2. The contribution model is not settled, so nothing here may assume that a contributor is a collaborator or that a maintainer is the only one who merges.
